proposito

Propósito de la tutoría

Una propuesta centrada en que el estudiante escriba, entienda y pueda explicar su propio código.

Objetivo general

Fortalecer las habilidades de desarrollo web frontend de los estudiantes, mediante práctica guiada, para que construyan sitios HTML/CSS estructurados, usen Git con criterio y sustenten sus decisiones técnicas y estéticas.

¿A quién está dirigida?

Estudiantes que necesiten reforzar HTML, CSS, Git o VS Code, o que quieran preparar mejor sus talleres, parciales y sustentaciones orales.

Objetivos específicos

  • Reconocer y aplicar la estructura semántica de un documento HTML.
  • Escribir CSS a partir de la cascada y el box model, no por ensayo y error.
  • Usar Git (commits, ramas, GitHub) como parte natural del flujo de trabajo.
  • Justificar cada decisión de código y de estética frente a la sustentación oral.
metodo

¿Cómo lograr que el estudiante entienda?

La tutoría pasa de copiar código ajeno a construir con sentido propio.

1. ¿QUÉ hago?

Identifico el problema

Reconozco qué necesito construir o resolver antes de escribir una sola línea.

Ej.: estructurar la navegación de un sitio.

2. ¿CÓMO lo hago?

Lo escribo y lo pruebo

Organizo el código paso a paso y verifico el resultado en el navegador.

Ej.: <nav>, <ul>, <li> y su jerarquía.

3. ¿POR QUÉ lo hago?

Justifico la decisión

Relaciono cada etiqueta o regla con la función real que cumple.

Ej.: por qué <nav> y no un <div> genérico.

Regla de la tutoría

Todo lo que se escribe se puede leer en voz alta y explicar: qué hace y por qué está ahí.

metodologia

Metodología de trabajo

Una secuencia corta y repetible para cada sesión, como los pasos de un mismo commit.

01

Diagnóstico inicial

Preguntas rápidas y una línea de código para ver qué domina y dónde se traba.

02

Explicación guiada

Concepto clave, ejemplo mínimo y por qué funciona así, no solo cómo se escribe.

03

Práctica activa

El estudiante escribe, ejecuta y corrige su propio código; el tutor solo orienta.

04

Verificación

Cierre breve: resuelve algo nuevo solo y explica cómo lo pensó.

Principio orientador

Menos copiar y pegar → más escribir y entender.

El estudiante participa, decide, recibe retroalimentación y vuelve a intentarlo.

sesiones

Las tres sesiones

Cada sesión corresponde a una capa real del trabajo: estructura, estilo y control de versiones.

sesion-1.html 30–35 min

Objetivo

Construir la estructura semántica de una página, sin depender de memorizar etiquetas sueltas.

Contenidos

Jerarquía de encabezados, párrafos y listas · enlaces y rutas · semántica básica (header, nav, main, footer).

Actividad central

Reto breve por parejas: uno propone la estructura, el otro la revisa con una checklist de semántica y jerarquía. Pregunta guía: "¿qué representa esta sección y por qué esta etiqueta?".

✓algo que hizo bien ⚠un error o vacío →una acción concreta para mejorar
sesion-2.css 35–40 min

Objetivo

Reforzar la cascada, el box model y el layout, relacionando cada propiedad con su efecto visual real.

Selectores y cascada

Entender qué regla gana y por qué.

Box model

Medir antes de ajustar: margin, border, padding, content.

Flexbox y grid

Elegir el layout según el problema, no por ensayo y error.

Responsive

Diseñar mobile-first y probar en distintos anchos.

Reto: ante un diseño de referencia, el estudiante decide qué propiedades usar y por qué, no solo copia valores.

sesion-3.md 35–40 min

Objetivo

Integrar HTML, CSS y Git en el proyecto propio, preparando la sustentación oral.

  1. Revisar el estado del proyecto y lo que falta.
  2. Decidir qué cambios hacer y en qué orden.
  3. Trabajar con Git: crear una rama, hacer commits claros.
  4. Verificar el sitio en el navegador tras cada cambio.
  5. Preparar la explicación para la sustentación oral.

Clave pedagógica

La meta no es "que funcione por accidente". La meta es que el estudiante explique qué escribió, por qué y qué decidió.

Retroalimentación entre pares

Checklist: estructura, estilos, mensajes de commit, accesibilidad básica y justificación de decisiones.

recursos

Estrategias, herramientas y recursos

Recursos sencillos para sostener la práctica y hacer visible el aprendizaje.

Estrategias pedagógicas

  • Aprendizaje activo
  • Preguntas guía
  • Pair programming
  • Depuración guiada (sin dar la respuesta)
  • Retroalimentación formativa

Herramientas

  • VS Code + Live Server
  • Git y GitHub
  • Consola del navegador (DevTools)
  • MDN Web Docs
  • Canal de dudas (WhatsApp/Discord)

Recursos técnicos

  • Plantilla base HTML/CSS
  • Ejercicios en un repositorio de GitHub
  • Ejemplos con errores para depurar
  • Guía de atajos de VS Code
  • Checklist de accesibilidad (WCAG)
evaluacion

Evaluación y seguimiento

Evaluar para mejorar: la evidencia se recoge durante toda la tutoría, no solo al final.

git diff

Diagnóstica · antes

Preguntas rápidas y un mini-reto sobre lo ya visto en clase, para ajustar la profundidad de la sesión.

commit

Formativa · durante

Observación directa + checklist + retroalimentación inmediata mientras el estudiante escribe código.

merge

Cierre · después

Mini-reto de cierre: resuelve algo nuevo y lo explica. Se deja una recomendación concreta para la próxima sesión.

Indicador de logro

El estudiante puede escribir, ejecutar y explicar su código de forma ordenada, sin depender de que se lo resuelvan.

cierre

Cierre de la propuesta

Una tutoría que conecta la sintaxis con el criterio.

¿Qué quiero que se lleve el estudiante?

  • Una forma ordenada de estructurar cualquier página.
  • Confianza para escribir CSS sin ensayo y error.
  • El hábito de usar Git como parte normal de su trabajo.
  • La costumbre de justificar cada decisión de código.
  • Una estrategia concreta para seguir aprendiendo solo.
